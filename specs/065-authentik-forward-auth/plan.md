# Implementation Plan: Authentik Forward-Auth for Tier 1b Apps

**Branch**: `065-authentik-forward-auth` | **Date**: 2026-05-23 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/065-authentik-forward-auth/spec.md`

## Summary

Add Authentik forward-auth to five Tier 1b apps (Prometheus, Alertmanager, Traefik dashboard, Loki UI, Node-RED) that have no native auth or weak auth. Traefik's `forwardAuth` middleware calls the Authentik embedded outpost's in-cluster service URL; the outpost checks the session cookie and returns 200 (allow) or 401 (redirect to Authentik login). One PR per app in risk order; Prometheus first (validates the pattern + scrape exemption logic). Shared Middleware resource created in PR 1 and reused by all subsequent PRs.

## Technical Context

**Language/Version**: YAML (Kubernetes manifests + Traefik CRDs)  
**Primary Dependencies**: Authentik embedded outpost (spec 063), Traefik v3 (existing), kube-prometheus-stack (existing), Loki (existing), Node-RED (existing, ArgoCD-managed)  
**Storage**: N/A — purely configuration; no new PVCs  
**Testing**: Manual browser verification per app; Traefik + Authentik logs for debugging  
**Target Platform**: K3s arm64, Traefik v3, Authentik v2026.x  
**Project Type**: Infrastructure configuration (Kubernetes manifests)  
**Performance Goals**: Auth check latency <200ms (outpost is in-cluster, single hop)  
**Constraints**: forwardAuth URL MUST use in-cluster service (hairpin NAT); Prometheus/Alertmanager scrape paths must bypass auth; Node-RED WebSocket must remain functional  
**Scale/Scope**: 5 apps, single admin user initially

## Key Technical Decisions

1. **Single shared Middleware** in `traefik` namespace — cross-namespace reference works in Traefik v3 (R1). Reference syntax in IngressRoute: `name: authentik-forward-auth, namespace: traefik`.

2. **forwardAuth URL** (mandatory): `http://authentik-server.authentik.svc.cluster.local/outpost.goauthentik.io/auth/traefik` — never the external hostname (R1, hairpin NAT).

3. **Scrape path exemptions** (R2): Split IngressRoute rules with explicit `priority` values. Scrape paths (priority 20, no middleware) win over catch-all browser rule (priority 10, with middleware).

4. **Proxy Provider mode**: Forward auth (single application) — not Proxy mode (R3). Each app gets its own provider with `External host` set to its fleet1.lan URL.

5. **Node-RED WebSocket** (R4): Deploy with full-route forward-auth first; split `/comms` to no-auth rule only if WebSocket editor breaks.

6. **home-automation TLSOption bug**: The existing `node-red-fleet1-lan` IngressRoute has a broken cross-namespace TLSOption reference. PR 5 fixes this to `tls: {}` at the same time as adding forward-auth. `home-assistant-fleet1-lan` and `influxdb-fleet1-lan` also have this bug but are out of scope — flagged for a follow-up.
