# Implementation Plan: Vaultwarden Password Vault

**Branch**: `066-vaultwarden-vault` | **Date**: 2026-05-22 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/066-vaultwarden-vault/spec.md`

## Summary

Deploy Vaultwarden (Bitwarden-compatible password manager) as the cluster's out-of-band recovery vault using the guerzon/vaultwarden community Helm chart, managed by ArgoCD. The critical design constraint is that Vaultwarden must be reachable independently of Authentik — no forward-auth middleware, no device-mTLS (which would create a circular dependency with the device cert it might store). TLS is provided by the existing fleet1.lan wildcard cert via Traefik's TLSStore. Persistent state lives on a 1Gi Longhorn PVC. Admin token is sealed via Bitnami Sealed Secrets.

**Scale/Scope**: Single replica, single admin user

**Design note — no device-mTLS**: All existing fleet1.lan services use the `device-mtls` TLS option. Vaultwarden is explicitly excluded from this — it is the recovery toolchain for device certs and MFA seeds. Requiring a device cert to reach the vault creates a circular dependency: losing the device cert also locks you out of the vault that stores the recovery path. Standard TLS via TLSStore (SNI-selected wildcard) is sufficient; network access is gated by Tailscale for remote access.
