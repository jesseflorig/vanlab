# Implementation Plan: NVR Host Monitoring and Alerting

**Branch**: `068-nvr-monitoring` | **Date**: 2026-06-03 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/068-nvr-monitoring/spec.md`

## Summary

Add monitoring for the NVR host (10.1.10.11, Intel NUC 11 running Frigate + Hailo-8) which powers off unexpectedly and has no visibility. Install `prometheus-node-exporter` and Alloy on the NVR host via the existing `nvr-provision.yml` playbook; add a `ScrapeConfig` CRD and `PrometheusRule` to the existing kube-prometheus-stack; configure an `AlertmanagerConfig` to fire a webhook to Home Assistant when the host goes offline; expose Loki on a NodePort for log ingestion from outside the cluster.

## Technical Context

**Language/Version**: YAML (Ansible 2.x + Kubernetes manifests) — existing project conventions
**Primary Dependencies**: `prometheus-node-exporter` (apt), Grafana Alloy (apt, Grafana repo), `ScrapeConfig`/`PrometheusRule`/`AlertmanagerConfig` CRDs (monitoring.coreos.com), kube-prometheus-stack (already deployed), Loki (already deployed), Home Assistant (already running at `home-assistant.home-automation.svc.cluster.local:8080`)
**Storage**: N/A — no new PVCs; metrics and logs flow into existing Prometheus/Loki stores
**Testing**: Manual verification per quickstart.md Step 4
**Target Platform**: NVR host (Ubuntu/Debian amd64) + K3s cluster (Raspberry Pi arm64)
**Project Type**: Network/observability infrastructure configuration
**Performance Goals**: Metrics visible within 60s; logs visible within 60s; alert fires within 5 minutes of host going offline
**Constraints**: NVR host is external to K8s cluster — cannot use cluster-internal service discovery or DNS; Loki endpoint must be reachable over VLAN10→VLAN20 boundary
**Scale/Scope**: 1 host, 2 firewall rules, 5 Kubernetes resources, 2 new host-side services

A new ArgoCD application `monitoring-nvr` manages this folder independently from the existing `monitoring-apps` (OPNsense exporter) application.
